# 机器人控制与副机部署

微信、DSH、WeChatAgent 和 GPT-SoVITS 在运行机器人的同一台电脑上工作。可部署到日常使用的主电脑，也可放在推流副机；两处均可选择 UIA 或 OCR 快速链路。没有独立“副机模式”，也没有主副机通信或跨机分发回复任务。已有迁移、路径配置和 OBS 音频检查工具继续保留。控制台仅监听本机 127.0.0.1，不提供局域网远程控制。

界面模拟和数据库读取不能保证不触发微信验证、重新登录或其他风控。2026 年 10 月 29 日本机验收后曾观察到要求重新登录的提示，原因未确认，现场操作随即停止；这不等于已经确认封号。当前状态和证据见 [显示验收矩阵](DISPLAY_ACCEPTANCE_MATRIX.md)。

在“电脑使用方式”中，“UIA 快速模式”开启时使用 UIA 控件链路，关闭时使用 OCR 快速定位与焦点交接。另有“文字逐字输入”开关，默认关闭，仅在 OCR 下将文字正文由快速粘贴改为逐字输入；UIA 始终快速粘贴，该选项在 UIA 下不可操作但保留原选择。联系人搜索词仍快速粘贴，图片、GIF 和语音不受正文输入选项影响。UIA 下独立保留“微信离屏”开关。旧共享电脑开关及关闭后的长期前台分支不再作为当前选项。具体入口见 [日常使用](DAILY_USE.md)，实现与已有耗时比较见 [发送链路说明](SENDER_MODES_2026_10_31.md)。

现行交互策略统一使用 `focus-handoff`，不再由旧 `foreground` 选择恢复长期前台链路。OCR 正文输入方式独立保存，缺省为 `paste`，启用逐字输入时为 `humanized`；UIA 始终使用 `paste`。旧配置读取后不能重新启用已移除的运行分支。两种链路都不承诺完全后台发送，结果不确定时不能换另一通道重发。

**历史 OCR 名称搜索验收：** 没有公开微信号的私聊使用当时数据库中唯一映射的备注或昵称搜索，曾在一条真实私聊回复中取得唯一数据库回执，含导航连续前台占用为 1,375 毫秒。内部稳定 ID 用于选择、授权和回执，没有直接当作可搜索微信号；群聊使用唯一完整群名，名称冲突时停止。当时搜索词和正文均粘贴后专用 Return，没有查询读回或额外联系人资料操作。该单例不保证所有联系人或一秒以内，也不代表当前可选逐字输入的耗时。

OCR 语音在开始和提交时借用前台，UIA 语音在开始后归还焦点，录制与定向提交在后台完成。录音期间在其他应用中的普通操作可以继续；需要停止本次录音的真实打断，只有在原窗口与采集会话仍属于当前尝试、尚未提交时，才尝试 Esc。确认原采集结束、取消输入完整生效且没有提交后，队列才允许新 ID 重新录制；未能确认取消或提交结果未知时保留待确认记录，不重发。现场已验证的具体打断类型与版本见显示验收矩阵，不能把单次测试扩大到所有操作情形。

**历史 OCR 共享链路验收（保留当时结果，不是当前开关说明）：** 当时要求可用的返回窗口和已配置的 CABLE 线路。连续操作导致无法安全切回时，程序停止播放并保留待确认状态；微信尚未取消的录音可能到自身时限自动发送。本机文件传输助手已完成自动文字粘贴发送、原生语音后台录音发送、数据库回执、焦点与鼠标归还，以及预热版本的实际验收。独立可见测试窗分别验证了三次合成鼠标移动和真人约 0.8 秒的鼠标移动；两次测试均在后台活动后继续录音、正常提交，并归还焦点和最后鼠标位置。真人测试记录到 260 次非注入移动，数据库回执为 5.16 秒，累计前台约 2.68 秒，不含新联系人导航；测试器未生成任何键鼠输入。实际收到的语音完整覆盖源音频，未检测到额外静音，离线识别全文与源音频一致；测试后六个默认音频角色已恢复。此前人工分步语音通过手机试听，此次自动语音仍未经手机人工试听或音色确认。真人持续使用鼠标和键盘、任意联系人和长期连续运行仍待验证；副屏后续已有定位与语音单例，完整导航及当前安全修订的状态见 [显示验收矩阵](DISPLAY_ACCEPTANCE_MATRIX.md)；它仍需短暂借用前台，`productionReady` 保持为 `false`。详见 [Qt 发送验证记录](QT_VISUAL_DRIVER.md#单屏语音交接与快速粘贴实验)。

首次源码部署还需要独立安装的 npm（可随 Node.js 安装）和匹配版本的 `wx_key.dll` 读取组件。DSH 自带 Node 不一定附带 npm。读取组件可从用户准备的 WeFlow/读取组件目录导入，或单独复制主机已经校验过的这个组件文件；源码包不分发 DLL。组件版本不匹配会拒绝，不能仅以“已安装 DSH、微信、OBS”视为全部依赖齐全。

**历史连续回复验收：** 代码已接入本地账号连接、好友与群聊多选、Qt 界面发送、原生语音队列、启动管理及消息游标。2026-10-29 正式服务完成同一真实好友连续三轮文字自动回复，数据库入站、DSH 生成、界面发送与唯一回执均已确认，用户也确认收到；群成员真实 @ 后的文字回复也已取得数据库回执和用户确认。随后修复等待空闲期间反复借还焦点的问题；新的生产跟踪样本中，每次文字提交只有一次取焦点和归还，视觉闪动是否消失仍待用户反馈。最新数据库快照已确认私聊 5 轮、群聊 7 轮共 12 段群回复全部送达，快照时没有待处理回复，自动回复已恢复；这不表示全部验收完成。任意联系人、长期运行、群语音和副机部署未被上述单例覆盖。当前没有副机；显示环境定位的独立结果见 [显示验收矩阵](DISPLAY_ACCEPTANCE_MATRIX.md)。

## 控制台入口

在“聊天”管理回复对象及各聊天的设置。“概览 → 电脑使用方式”用于选择 UIA 或 OCR，“能力 → 语音服务”用于配置识别和合成。

- 在“聊天 → 添加聊天”搜索本机微信好友或群聊，最多选择 32 个。聊天列表直接使用当前回复对象名单，尚未产生 DSH 会话的对象也会显示。移出聊天后，该对象尚未发送的回复授权失效。
- **自动选择回复形式**：机器人根据对话选择文字、原生语音、导入的图片或 GIF 表情，也可通过文字发送网址；没有单独的“回复方式”栏。已进入队列的回复保留原形式，发送不确定时不会自动改用其他形式重发。
- 在“语音服务”中选择本地识别或合成，可在右侧选择对应的 faster-whisper 识别方案或机器人音色。底部的“保存语音服务”同时保存两项设置。点击识别方案旁的“使用此方案”后，模型会常驻并处理后续语音和视频音轨。展开“编辑权重与参考音频”可编辑合成方案，内置达妮娅的修改会另存为副本。点击音色旁的“使用此方案”可加载保存的合成权重与参考音频。
- **模型状态**：点击“使用此方案”后启动本地语音服务并加载所选方案。保存方案后需再次点击以应用新的权重和参考音频。服务确认两份权重和参考音频后才合成，一整条回复使用同一模型。日常不需要另开语音服务；模型加载期间不占用微信焦点。
- 在“表情包 → 本地图片与 GIF”导入本机 PNG、JPEG、GIF，保存名称与标签供机器人选择。GIF 保留原文件，通过微信发送为动态表情。该区与“账号共享表情池”分别保存内容，读取服务离线时也能管理本地素材。文件和动画规模限制见 [日常使用](DAILY_USE.md#图片gif-表情和链接)。
- **操作保护**：两条链路始终保留保护，没有可关闭的独立开关。有人操作运行机器的鼠标或键盘时，停止相应前台输入并保留本次进度。已确认的后台录音阶段允许使用其他窗口；UIA 后台提交不再借用第二段前台，OCR 提交仍等待安全间隙。部署到另一台电脑时，主电脑的操作不会触发那台电脑的本地监控。
- **UIA 快速模式**：没有旧选择时默认关闭，已保存的选择保留。开启走 UIA，关闭走 OCR 快速链路，二者均借用焦点并归还。UIA 适配微信 4.1.15.56，停服时可先保存选择，启动或运行中切换时核对控件。缺少必要控件或绑定变化时暂停。旧后台注入设置不会自动开启 UIA，原生文字候选仍保持阻断。发送需原队列和数据库回执确认。详见 [UIA 控件模式](BACKGROUND_CONTROLS.md)。
- **文字逐字输入**：默认关闭并快速粘贴，只改变 OCR 文字正文；UIA 下不可选但保留设置，联系人搜索、图片、GIF 和语音不受影响。开启后正文占用前台的时间随字数和输入间隔增长。
- **微信离屏**：UIA 下独立选择窗口停放，关闭时恢复程序管理的位置。它不改变发送链路，也不保证不占用焦点。现有 UIA 无障碍 gate 保留，本次整合没有删除或扩展它。
- **发送与设备检查**：显示当前账号绑定、窗口标定、组件和语音文件是否齐全；可枚举并选择本机 VB-CABLE 线路，不需手填设备 ID。准备完成、服务已停止后才可开启“允许前台自动回复”，保存后仍需点击“启动服务”。读取页面和枚举设备不截图、不操作微信、不打开音频流，也不验证 OBS 是否隔离。

在“聊天”添加或移出对象会直接保存，正在运行的机器人会使用新名单。概览中的交互开关切换后会保存。语音方案在内置能力“语音服务”中保存，点击“使用此方案”加载本地模型。各项保存会核对版本，避免旧页面覆盖其他窗口的新修改。未保存的模型编辑会保留到页面切换后，可点击“放弃修改并重新载入”丢弃。

“电脑使用方式”中的耗时按每一次连续借用前台显示，并列出最长的一次。以下 2026-10-29 数值属于旧 OCR 快速粘贴样本，可作默认粘贴方式的参考，不是当前代码性能保证，也不适用于逐字输入。该次联系人定位、切换与准备都应纳入，确认还回焦点后才开始另一段；语音在后台录制的等待不计入。未包含联系人切换的记录会单独标注，旧累计数据不会冒充新指标。2026-10-29 文件传输助手实测中，文字切换、粘贴、回车发送和归还共 813 毫秒；最终语音切换、开始录音和归还共 968 毫秒，结束录音、点击发送和归还为 281 毫秒。自动 Esc 取消另测为 63 毫秒，从微信已在前台时起算。完整范围与版本见 [显示验收矩阵](DISPLAY_ACCEPTANCE_MATRIX.md)；这些是受控单例，不保证任意负载都低于一秒。副屏与主屏仍共享焦点。

“允许前台自动回复”控制发送许可，操作保护是界面模拟的固定行为。运行时关闭自动回复许可会阻止新提交；已经开始的录音仍要正常停止或取消，已发送的消息不会撤回。UIA 和 OCR 都在需要的准备与输入阶段借用前台；OCR 语音提交再次借用，UIA 语音提交在后台完成。逐字正文期间同样占用真实键盘焦点。将机器人部署到另一台电脑可把这些占用转移到那台电脑。停止服务会等待输入和录音清理完成，不能用强制结束进程代替。

界面模式账号拒绝缺少来源授权的主动消息和定时助手通知；重启或重连旧发送后端不会自动恢复这些分支。已授权的自动回复可以从明确导入的素材中选择静态图片或 GIF，仍受同一对象授权与队列约束。

## 核验暂停与手动恢复

窗口、布局或账号核验失败会保存暂停状态；反复重启服务不会自动解除。先正常停止机器人，手动确认微信已登录并检查待发回复，然后在“设置 → 诊断 → 发送与设备检查”点击“检查本机配置”，勾选确认，再点“恢复发送核验”。状态或账号在检查后发生变化时，需要重新检查。

恢复只解除本次准备核验暂停，不启动服务，不改变原有发送许可，也不删除待发草稿、结果不确定的语音或其清理屏障。若仍有录音、发送或停止清理过程，恢复入口保持不可用。普通鼠标键盘活动引起的暂缓不要求使用此入口。已完成的正文输入保留断点与原窗口绑定，在可恢复时只继续未执行的步骤；OCR 逐字输入保留已输入进度，不从头重复正文。搜索被打断则重新搜索。发送键已执行且结果未知时只查询回执，不再次发送。

图片或 GIF 不按文字正文的断点直接续接。当前实例仍能确认原图片草稿时可继续提交；草稿依据丢失、程序重启或界面状态无法确认时暂停。此时在“聊天 → 选择对应聊天 → 发送队列”按恢复提示停止服务，手动检查微信并清理未发送草稿，再确认解除这次草稿占用。解除不重发原任务，也不把未知发送结果记为成功。

确实遗留未知录音时，使用独立的“检查语音恢复状态”。先停止机器人，手动确认微信录音已结束，并查看对应聊天的消息结果，再勾选这两项确认并点击“解除这次录音占用”。账号、记录或运行状态变化后需要重新检查。此操作保留原发送记录及未知结果，不补发原语音、不启动服务、不改变发送许可；它只释放经人工确认已结束的录音占用，不能代替普通键鼠中断后的继续操作。

## 首次连接与启动

1. 配置本机 DSH 路径并打开控制台，微信保持登录。
2. 在“连接本机微信”的“本机读取组件来源”选择 WeFlow 安装目录，或填写 `wx_key.dll` 的完整路径，点击“校验并导入读取组件”。只复制固定 SHA-256 匹配的组件，不执行、不加载、不替换已有文件。随后填写本机微信数据位置并连接；首次准备独立读取环境，提示组件就绪后再手动退出并重新登录同一账号。
3. 连接成功会保存当前 Windows 用户保护的凭据，并激活同一账号的正式读取配置与 DSH 账号记录。已有有效本地配置可用“激活已有读取配置”。激活不发送消息。
4. 在“准备本机组件”入口按锁文件安装 DSH 插件依赖，再构建原生模块并准备本地 OCR。安装器优先选择 DSH 同目录 npm，缺失时查找本机独立安装的 npm；均由 DSH Node 执行 `npm ci --ignore-scripts`，排除 Codex 路径，不执行依赖安装脚本。找不到 npm 会提示先准备它。该步骤不代替窗口标定或实际聊天身份核验。
5. 选择好友或群聊和语音方案，完成本机窗口标定；语音还需虚拟音频通道与录音按钮模板。在“设置 → 诊断 → 发送与设备检查”枚举并选择 VB-CABLE，检查状态并保存发送许可。
6. 先执行“准备 DSH 连接配置”，把插件路径更新为本机目录；也可执行 `secondary-computer.ps1 -Task prepare`。随后在 DSH 启用本项目 packages/dsh-social-bridge-plugin 插件，从托盘完全退出并重开 DSH，让其加载本机路径和当前账号记录。
7. 配置完整后使用控制台“启动服务”。管理器按 wechat-ui 模式启动界面服务和选定好友／群聊 Reader，并核对当前机器的微信版本与窗口标定。

窗口和音频设备标定仍是每台机器的准备步骤，尚不能跳过现场核验自动完成。详见 [界面适配](WECHAT_UI_AUTOMATION.md) 和 [DSH 本地运行](DSH_LOCAL_RUNTIME.md)。

目前窗口矩形标定使用 [Qt 标定工具](QT_VISUAL_DRIVER.md) 的本机布局 JSON 与命令行入口，尚无可视化拖框向导。普通 Qt 标定生成文字发送布局；`--voice-plan` 提供只读录音按钮模板采集入口，需要操作者在文件传输助手手动显示录音界面并在采集后及时取消。工具本身不录音、不点击，也不替操作者取消。不能用旧机器模板或手写“已验证”标志代替。缺少配置时语音启用会明确停止。发送设置接口与保存语义见 [本机启用设置](UI_RUNTIME_CONTROLS.md)。

OCR 链路保留 `--focus-plan` 采集微信非前台时的空白标题栏模板，用于系统拒绝直接切换焦点时的一次普通点击。采集时保持另一个应用在前台，同时露出该微信区域；工具只读检查两帧，不激活或点击。普通活动窗口模板不能代替这份模板。UIA 通过实时控件定位，不使用 OCR 模板执行。运行时保持当前 Windows 会话未锁定、微信已登录且未最小化；首次搜索切换联系人仍会占用前台。已保存的窗口尺寸与 DPI 布局可自动匹配复用；对于微信 4.1.15.56 暗色界面、DPI 96–240，OCR 未知布局也会从当前窗口自动识别，宽度、高度可以独立变化，不要求保持原长宽比。后台定位不取得键鼠焦点；实际发送前仍核对账号、数据库目标映射和当前窗口。当前快速链路不恢复旧普通模式的空草稿检查。遮挡、识别失败或未适配的版本与主题会暂停，不猜测坐标。副屏已有显示组合的历史定位实测，范围见 [Qt 界面适配](QT_VISUAL_DRIVER.md)。



## 语音与推流设置

回复音频拆成多条不超过约 7.5 秒的原生语音气泡，在采样边界附近寻找较安静的位置，保留全部采样。每段取得唯一数据库回执后才发送下一段；回执证明语音消息记录，不证明手机听感或音色。

当前发送器**不修改 Windows 默认声音设备**。副机需预先把三个默认录音角色设为配置的 CABLE Output，播放只指向对应 CABLE Input。项目核对微信实际录音会话和设备；不匹配时拒绝录制或停止播放。“路由安全”在此表示设置未改变，不能描述为已替用户恢复麦克风。

在共享电脑上也是同一要求。控制台选择 CABLE 只保存绑定，不会修改 Windows 默认角色；需要真实麦克风的会议、游戏语音或录音软件应明确选择真实设备。发送器不会替这些软件切换麦克风，项目停止后也不会改回默认设备；是否恢复由操作者根据后续用途决定。

OBS 固定选择实际麦克风和采集卡，避免使用跟随系统默认的输入。虚拟语音通道不进入直播、监听或 Windows“侦听”；视频捕获主电脑或采集卡，避免直播副机微信桌面。详见 [副机音频与桌面部署说明](SECONDARY_PC_DEPLOYMENT.md)。

## 停止、恢复与历史记录

停止服务会取消操作并等待原生执行器与 Reader 真正退出。录音、输入或退出无法确认时保留屏障，不自动换 ID 重发，也不因重启就视作成功。

Reader 保存游标和待接收事件，桥接确认接收后才推进游标。服务恢复后自动分批补读离线消息，进度保存在本机。群聊和私聊均按当前聊天的原有规则判断是否回复，包括参与方式、唤醒条件和助手权限。可在“设置 → 诊断 → 读取记录修复”查看进度。首次启用聊天名单时建立当前基线。

旧版恢复被中断时，页面仍提供停服后还原原记录的入口。回滚完成后启动服务继续自动补读。草稿冲突、未知录音或原生进程失联仍需核对微信实际状态。

已确认和安全取消的任务按 ID 归档，活跃队列不因累计 256 条历史消息而停止。归档保留原 ID、绑定和回执；旧 ID 不会重发。未知状态和残留草稿不靠归档解锁。已确认语音的匹配 WAV 可清理，取消任务音频保留。

## 迁移源码与副机路径

导出包含当前未提交源码修改，排除已知私有状态、非示例配置、依赖、模型和微信数据：

    powershell -NoProfile -File .\scripts\export-secondary.ps1

不要复制主机 state、DPAPI 密文、虚拟环境、窗口句柄、设备 ID、发送队列或账号授权。导出不扫描任意源码正文中的私密内容。

在目标电脑的新目录解压，按软件已安装的前提，将 config/secondary-computer.example.json 复制为本机忽略配置并填写路径。权重和参考音频必须处于配置的 GPT-SoVITS 目录内。

    powershell -NoProfile -File .\scripts\secondary-computer.ps1 -Task configure -DshRoot "D:\DeepSeek Harness" -SettingsFile ".\config\secondary-computer.json"
    powershell -NoProfile -File .\scripts\secondary-computer.ps1 -Task console

配置只接受没有旧正式配置和运行状态的新目录，校验路径并生成本机配置，不登录微信、不设置音频设备、不启动自动回复。点击“使用此方案”会在后台启动并加载本地语音服务；`secondary-computer.ps1 -Task voice-server` 保留作独立维护入口，日常无需额外执行。

完成账号连接激活、组件准备和本机标定后：

    powershell -NoProfile -File .\scripts\secondary-computer.ps1 -Task start
    powershell -NoProfile -File .\scripts\secondary-computer.ps1 -Task status
    powershell -NoProfile -File .\scripts\secondary-computer.ps1 -Task stop

这些入口使用副机 DSH 自带运行时并移除继承的 Codex 环境变量。源码包不包含本机编译产物；无副机阶段只能覆盖配置、组件和离线生命周期测试。
# 音视频读取补充

语音识别和合成各有独立的本地、云端选项。视频复用选定的语音识别后端处理音轨，采样帧由本机提取。副机准备完 Reader 后按所选模式执行 `npm run media:prepare`，再执行 `npm run media:check` 验证。本地模型、虚拟环境和云端凭据均在目标电脑配置。详见 [音视频接收](AUDIO_VIDEO_INPUT.md)。

# 回复防重复与回执核验

每批回复都有独立的投递 ID。桥接服务先保存目标聊天和已生成的回复，再交给桌面发送器。断开连接或重启后，服务通过原 ID 查询进度。不同批次可以正常发送相同文字。

文字和配图持久入队后，OneBot 即可返回待处理状态。排队和回执等待期间，其他聊天仍可登记投递。

## 如何确认送达

文字回执核对当前账号、目标聊天、完整文字和发送前已有的消息。回执查询按原提交的时间范围读取各分片的出站记录。匹配到新的本地消息后，发送器等待该条消息取得非零服务器 ID，再确认送达。已经确认的文字或表情会复用原结果。

界面显示“未确认”时，可以在该聊天的发送队列中核对状态。响应丢失或回执不明确时，发送器保留原记录，超时或重启后仍可沿原编号只读核验。后续批次仍可以继续处理。

## 中断后如何恢复

桥接服务按原账号、聊天授权和投递 ID 查询桌面发送器的活动任务和归档。已经入队的任务沿原记录查回执。如果原命令已保存，且查询证实它从未入队，服务会重新核对授权，再用原 ID 继续入队。账号变化或存储无法读取时，任务保留供核对。

文件在恢复期间使用原暂存内容，语音在执行器确认入队前保留原音频。待投递的回复记录在工作区 `state/social-messages.json` 的 `pendingReplies` 中，文字投递记录位于 `state/text-deliveries/`。这些记录包含聊天信息。排查或迁移时请保留它们，分享日志前请脱敏。

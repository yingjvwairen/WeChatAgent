# DSH 离线与重连消息处理

DSH 退出、插件接口不可用或插件实例更换后，微信仍可接收消息。本项目默认保留聊天历史，但不把离线期间的旧闲聊逐条补答。

## 当前行为

读取器还按数据库分片保存已扫描的本地行号。微信新写入的旧时间戳消息超出近期回扫窗口时，仍会保存到聊天历史。系统时钟回拨时，控制台会提示校准时间，原游标保留，校准后继续处理。

### Reader 或消息桥接停机

Reader 按账号和已授权聊天保存扫描进度。每次桥接连接或重连都会建立收件边界。即使 Reader 持续运行，尚未确认的积压事件也按补读处理，重连当秒按握手时已经存在的分片和本地行区分新旧消息。保存新选聊天前，控制台为当前账号和聊天授权记录各分片的现有行号。Reader 从这条边界开始读取，保存后在首轮扫描前到达的消息也会入队。已经存在的行即使晚到服务器 ID，仍属于边界之前的记录。正常轮询每跨过 30 秒检查点会补扫最近 5 分钟，迟写入数据库的行按原消息 ID 去重。重启后按时间窗口补读中断期间的消息，按创建时间、本地行号、分片排序，每批最多 256 条。需要服务器消息 ID 的文字、卡片和附件会保留其本地行位置，直到取得 ID 再入队。临时无法读取分片时保留进度，等待下次扫描。持久队列最多容纳 1,024 条未确认输入，队列满时读取端等待消费。未签收消息与桥接缓冲区中的保留记录都会保护附件引用，模型尚未消费的附件可在桥接重启后继续读取。DSH 最多并行处理八个聊天的入站事件，Realtime 使用独立的额度。等待 Realtime 的事件保留在 Reader，同一聊天保持原顺序。

桥接把输入写入会话记录后，Reader 才确认这一项。连接中断后再次收到相同消息 ID，会话可以确认已保存的记录。移出名单会撤销原会话授权，重新加入后旧授权的事件失效。补读期间，社交模式每个聊天保留最后一条符合唤醒条件的发言用于一次回复判断，其余作为上下文。助手模式默认保留历史。在控制台启用助手补读，或变更管理员名单、助手会话名单和聊天授权批次时，系统从保存后的下一秒建立新的补读边界。早于边界的消息只用于历史。Reader 和桥接都会复核该边界、聊天授权和发件人角色。符合唤醒规则的最后一条消息可进入原有助手或群聊流程。实时语音服务不会为历史补读逐条生成回复。补读的“停止分段”只影响该指令之前收到的消息所对应的待发回复。补读的“取消任务”需要指定任务编号。

“设置 → 诊断 → 读取进度”显示当前授权聊天的扫描时间、补读目标和待确认数。单个聊天扫描失败时，页面在该聊天下显示原因，其他聊天继续同步。扫描连接分批重新发现分片。所有已授权聊天扫描失败时，整体读取显示异常，最后一次成功扫描的时间保持原值。Reader 停止后仍可查看该账号持久化的进度。通过本机 Reader API 查看时，可在状态请求中加上 `?progress=1`。

重连时，如果某个聊天的边界无法读取，该聊天在重连当秒的消息只用于上下文，已入库的其他聊天继续交付。去重记录按各聊天的扫描进度清理，停机超过一天时仍保留可能被补扫的已确认消息编号。

如果收件队列已满且没有可交付的消息，Reader 会把最早受阻的一条新消息保存到聊天上下文。只剩等待补读结束的回复候选时，则先保存最早的候选。转为上下文的消息保留原来的身份和附件，为扫描腾出位置。

补读的图片、表情、视频帧、语音和转发附件可在后续回复轮次作为背景。当前消息的附件优先，历史附件按原发件人与消息关联，并继续遵守账号、聊天和插件授权。助手可以按当前请求处理同一发件人此前授权的文件。历史内容不会单独触发回复或任务。

Reader 首次分派事件时保存 DSH 或 Realtime 处理路径，助手模式统一走 DSH。重连后沿用该路径，首次补读的历史消息走 DSH。Realtime 回复的决定写入待发送队列后，Reader 即可确认收件并继续同一聊天的下一条消息。待发送回复按聊天保序，重启后恢复原决定和投递编号。账号或聊天授权批次改变时结束旧任务。

### DSH 离线

- 桥接服务每两秒检查本机 DSH 插件，在模型请求与文字发送前再次确认。检查不调用模型。
- 离线期间的新消息仍写入聊天档案，调度缓冲标记为已跳过。重连后的新消息触发回复，最近的离线消息及其仍有授权的附件可作为背景。读取器晚到的旧事件同样检查恢复边界。
- 连接边界与插件实例标识保存在 `state/social-messages.json` 的 `dshConnection` 字段中，重启桥接不会重新放出已跳过的输入。首次升级会停止旧缓冲中尚未完成的历史批次，聊天记录继续保留。
- 旧模型结果在断连后晚到时不再发送；尚未发送的旧文字、配图草稿会取消。已提交的正文、语音和表情沿原 ID 查询桌面回执，重启桥接也能更新会话记录。尚未被桌面接受的意图在断线核对时不会重新入队。
- 助手模式下，已登记而尚未完成的任务在 DSH 重启后进入中断待检查状态，包括排队任务。管理员可通过“任务列表”查看，并用现有“继续任务 T编号 补充要求”明确继续。
- 离线期间尚未被 DSH 接收的新任务仅保留为聊天资料，不会在重连时自动执行；恢复后请管理员重新发送请求。
- 新的请求携带插件实例标识。若插件在健康检查与提交之间重启，服务端在接收任务前拒绝旧实例请求，避免跨实例补交旧批次。

不会删除聊天档案、人格、表情、账号配置或 DSH 会话。离线旧消息可以作为后续接话的背景，但不属于当前执行授权。系统不会为每次断连向微信发送额外提示。

## 应用更新

更新桥接与 DSH 插件源码后，需要重启 WeChatAgent 后台并从托盘完整退出、重开 DSH，以加载实例标识和队列恢复规则。其他设备的旧安装包不会自动获得源码改动。

排查时可在 `state/logs/bridge.stdout.log` 查找 `connection=offline`、`connection=ready`、`replay=disabled` 和 `input_archived`。无需删除 `social-messages.json` 或清空 DSH 历史。

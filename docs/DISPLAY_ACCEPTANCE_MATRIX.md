## 定位覆盖与环境限制

机器可读矩阵预留了 60 个真实环境场景：七档 DPI × 六种宽高组合；七档 DPI 下分别切换系统分辨率；相邻缩放档位以及 96↔240 的边界切换；分辨率和缩放同时变化；同缩放跨屏和不同缩放跨屏。当前仅要求这些场景的定位，历史发送列保留，不再逐组合执行发送。

当前设备常规选项能够执行的各档形状、同 DPI 分辨率变化、指定缩放转换及跨屏项目均已有对应证据。早前不足以证明指定转换的观察及所有中止记录仍保留；后续成功仅用各自新现场报告登记。250% 在本机常规缩放选项中不可用，因此涉及它的 10 项不算通过，整体也不宣称覆盖所有 Windows 显示环境。

系统分辨率切换必须记录 Windows 显示模式的前后宽高，不能用微信客户区大小代替。只使用当前显示设备提供的模式；设备或常规设置未提供的档位标为环境不可用，不据此改成代码不支持。窗口必须处于可见、可核验的位置。

每个场景执行时记录：

1. 前后显示器模式、DPI、客户区尺寸及是否仍为同一窗口/进程；未取得的值写 `null`。
2. 自动定位和最终当前像素复核；离线候选不能替代现场复核。
3. 定位所用代码版本、证据类别，以及是否访问真实录音浮层。普通聊天布局中的录音入口与录音期间的取消/发送按钮分别记录，合成录音按钮几何不能冒充各 DPI 下真实浮层定位。

定位和当前像素复核通过后，更新 `displayLocationAcceptance.requiredCases` 中相应场景的状态、证据和 `accepted`。这个判断不要求发送消息。原六项完整流程及 `fullWorkflowAccepted` 继续作为历史定义保留，不能为满足新范围而把未执行的发送改成通过。真实好友连续回复、消息内容、语音音质及焦点归还另做独立验收。

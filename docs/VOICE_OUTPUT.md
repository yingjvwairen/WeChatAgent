# 机器人语音回复

在线社交聊天及已授权的助手任务均可选择简短语音回答。回复形式由对话与已授权能力决定，可组合文字、语音、图片、GIF、表情与链接。语音识别和合成使用该聊天已授权的语音插件。

## 配置服务

在“能力 → 语音服务”选择提供商和聊天授权。使用本机 GPT-SoVITS 或 Whisper 时，在同页配置 Python 和模型目录，开启“随应用启动”并保存。然后在语音配置里选择“WeChatAgent 托管服务”。该提供商使用界面选中的方案。“保存并使用”会立即加载新方案。

已启用的本地服务默认随桌面应用启动预热，机器人独立运行时也可持有服务。识别或合成的已授权路线全部切到云端时，后台释放对应的本机模型。切回本机路线时，程序会自动加载已选方案。桌面和机器人全部退出或失联后，程序释放本项目启动的本地服务。

详细参数见 [本地 GPT-SoVITS](LOCAL_GPT_SOVITS.md) 与 [本地 Whisper](LOCAL_WHISPER.md)。合成参数保留方案级语速、温度、Top K/Top P、重复惩罚、段落间隔和分句方式。请求显式语速优先于方案默认。

## 逐轮选择文字或语音

使用 DSH 生成回复时，先为该聊天启用一个语音合成插件并配置原生语音发送。模型可以结合当轮请求选择文字或语音，需要复制的链接和代码使用文字。语音插件也支持由 Realtime 服务直接处理对话，可在插件设置中选择回复方式。[语音对话插件设置](../optional-extensions/speech-synthesis/README.md#设置页)

助手模式也可启用语音直接对话。获准的语音交给 Realtime 模型处理，文字消息继续由 DSH 处理。私聊只接收已授权管理员的语音，群聊沿用会话的唤醒设置。Realtime 服务本轮只收到当前语音。

在启用“语音直接对话”的群聊里，微信原生的 @本账号 和 @所有人 都会唤醒群文字对话。群语音使用该聊天的唤醒设置，来源依照微信消息元数据判断。

Realtime 决定保存后，发送队列独立处理回复，同一聊天仍可继续接收消息。若进程重启时原语音尚未交给桌面发送队列且音频已丢失，发送器沿用已决定的文字回复。已交给桌面队列的语音继续查询原投递回执。

DSH 的语音回复持久登记后，OneBot 返回待处理状态。合成和桌面回执由后台分别处理。开始合成和交给桌面发送器前会复查原聊天的授权。重启后继续尚未开始的合成。已留下合成意图但未保存音频的任务标记为中断。

## 微信语音气泡

微信 4.2.0.53 的原生语音经同一桌面发送队列发送。先准备 VB-CABLE，把合成音频送到微信录音使用的端点；程序不会每条消息反复修改系统默认音频设备。OCR/UIA 定位在录音开始、提交或取消时使用，共享电脑的焦点只在需要操作时短暂切换。

用户输入导致录音中断时，取消当前录音并重新组织一次录音。未知提交状态只核对已有数据库回执，不自动重新发送同一投递。退出时等待录音与焦点清理完成，不能确认清理时保留进程供恢复。

缺少录音标定时，桌面队列结束尚未录制的分段。其他录音预检连续失败 30 秒也会结束未发出的分段。确认整条语音从未提交时，自动回复改发原文。手动暂停的任务等到恢复后再检查。

图片、表情、引用、转发、语音和视频由 Reader 从当前账号的数据库和附件中读取。语音识别需要对应聊天授权。[视频音轨与采样范围](IMAGE_INPUT.md#聊天内的视频采样)

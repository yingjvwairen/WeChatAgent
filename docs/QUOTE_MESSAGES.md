# 微信引用消息解析

接入 NT Reader → WechatOneBot → Social Bridge → DSH 的消息链，不修改人格卡，不增加独立模型调用。

## 接收与身份

支持本地类型 `49` 与 `(57 << 32) | 49`，同时要求完整 XML 的 `appmsg/type=57`。补查数据库原始 `message_content`，避免 CLI 的显示预览截掉引用原文。其他 appmsg 类型不因此作为普通文字放行。

当前回复来自 `appmsg/title`；引用历史来自 `refermsg`。保留原消息的服务器 ID（字符串，避免大整数精度损失）、发送者、显示名、时间、类型和正文。群聊 `fromusr` 是群号，引用发言人是 `chatusr`；私聊发言人来自 `fromusr`。

当前消息的发送者仍取数据库发送者，不被 XML 中的引用者替代。平台适配器根据当前账号及原群号计算引用来源关系，覆盖载荷中的关系标记；无法确认来源或来自另一群时标记未知。身份匹配只用于接话判断，不授予配置、工具或发送权限，也不证明那段话一定由当前人格发出。

## 模型上下文

`quoteReply` 作为有界结构经过 OneBot 归一化和聊天缓冲持久化。只保存一条当前发言，提示词中分别标注“被引用的历史消息”和“当前发言人的新回复”。引文中的标签会转义，规则变更指令作为历史聊天数据处理。

在群聊 `mention` 模式下，引用本账号的发言可触发决策，模型仍结合正文、相邻发言与上下文判断回应或沉默。引用其他人不自动触发；回复正文中的真实 @ 或唤醒词仍按既有规则处理。`hybrid` 模式继续通过普通消息批次判断。私聊继续按私聊规则处理。

## 边界

XML 上限 100,000 字符，回复保存至多 4,000 字符，引用原文至多 1,600 字符，嵌套引用最多展开 2 层；过长内容标注截断，模型批次仍遵守现有长度限制。DTD、ENTITY、无效 XML 和其他 subtype 被拒绝。

缺少原文时仍传递对方的新回复，并标明引用内容不可用。图片、表情、语音和视频须能绑定到当前聊天的原消息和本机已下载的附件，语音转写还需要聊天授权。文件引用可以显示文件名。媒体与转发条目的读取范围见[图片与视频](IMAGE_INPUT.md#聊天内的视频采样)。

## 原生引用发送

微信 4.2.0.53 支持在已授权的私聊和群聊中发送原生引用。模型在普通回复请求中选择要引用的消息。近期候选使用 `Q1`～`Q8`，历史查询使用 `H编号`。桥接层解析 `RESPOND: [QUOTE:编号] 正文`，将原消息的服务器 ID 随回复保存。重启后仍使用同一来源。系统通知和未知卡片只作为上下文。

发送器先在可见消息中查找原文，再按可用的控件、聊天记录搜索或有限滚动定位。对于图片等富媒体，可以用同一聊天中的邻近文字定位视口，再匹配原媒体。定位完成后，只关闭为本次查找打开的历史窗口。

相同的正文可能对应多条消息。只有新消息取得服务器回执，且其中的引用来源 ID 与请求一致，才会记为送达。来源已删除、不能唯一定位或操作被打断时，请在发送队列查看该任务。[桌面发送与恢复](FOREGROUND_INPUT.md#发送与恢复)

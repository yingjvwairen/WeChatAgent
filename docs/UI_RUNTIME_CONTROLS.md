# 界面机器人启用设置

控制台的“设置 → 诊断 → 发送与设备检查”管理本机发送许可和语音线路。读取页面不会创建配置、截图、操作微信、播放音频或连接语音模型服务。首次页面返回的是禁用的 Qt 配置；点击保存才写入 `state/ui-bridge/config.json`。

开启前需要当前账号的受保护 Reader 配置已激活、本机 Qt 标定与该账号及微信程序一致、界面组件已构建。语音模式还需要录音操作标定、GPT-SoVITS 当前选中权重及参考音频文件、语音组件，以及本机唯一的 VB-CABLE 输入输出设备。

标定文件存在只表示配置完整，不证明当前微信窗口、账号、收件人或草稿已经核对。实际发送按所选模式执行：普通模式保留草稿检查；“共享电脑短暂切换”的私聊搜索优先使用公开微信号，缺少时才使用当前数据库中唯一的备注／昵称；内部稳定 ID 继续用于选择、授权和回执。群聊使用新读取的唯一群名搜索已绑定群聊，并快速粘贴，按用户选择不读取查询或正文，也不检查输入框空白。共享文字使用一次专用 Return 提交，语音仍点击发送。该开关统一控制快粘贴、联系人快捷导航和语音焦点交接，副机方案保留；它不启用内存注入，也不等于完全无焦点占用。备注／昵称回退已在一条真实私聊回复中取得唯一数据库回执，含导航连续前台占用为 1,375 毫秒；该单例不保证所有联系人或一秒以内；不增加界面身份核验或查询、正文读回。设备枚举只读取 Windows 设备元数据，不打开音频流，也不证明 OBS 推流已隔离。

请先正常停止机器人和语音操作，再开启自动回复。保存只改变许可和设备配置；继续使用现有“启动服务”入口启动服务。运行时可以关闭许可，阻止新的提交；已开始的录音仍须正常停止或取消，已发送消息不会因此撤回。设备或许可配置改变后需要正常停止并重新启动。音频默认录音角色需要预先指向配置的 CABLE，程序保持现有默认设备设置，不在每次回复后切回物理麦克风。

普通用户活动发生在搜索过程中时，空闲后重新搜索；正文已粘贴而发送尚未执行时，保留同一任务的步骤，返回原微信窗口和输入框后继续，不重读正文。录音阶段允许既有规则下的其他应用操作；真正打断原录音时尝试 Esc 取消，只有明确确认旧录音已结束且未发送，才以新尝试 ID 等待重录。发送结果未知时只查询回执，不补发。共享模式不检查用户留下或修改的正文，步骤续接也不会再次比较正文。

搜索按 Return 后会等待页面呈现：标题已变化时采集间隔至少 35 毫秒的两帧稳定画面；标题不变时先等待至少 350 毫秒，再采集两帧，总等待不超过 600 毫秒。此等待不增加联系人资料识别或正文读取，也不能保证任意页面迟延都已结束。

## 本机接口

所有接口沿用控制台的 Host、Origin 和 `X-Console-Token` 检查。

- `GET /api/ui-runtime-controls`：返回 `revision`、`configured`、`enabled`、`canEnable`、`serviceRunning`、`blockers`，以及 `calibration`、`voice` 和 `replyMode`。`liveUiVerified`、`streamIsolationVerified` 恒为 false，不能把这些字段解释为实时校验成功。
- `GET /api/ui-runtime-controls/audio-devices`：只执行项目内 `AudioRouteProbe.exe --list`，返回 VB-CABLE 的 `devices` 和唯一匹配的 `pairs`。不提供物理麦克风选项，也不改变系统默认设备。
- `POST /api/ui-runtime-controls`：提交 `{expectedRevision,enabled,voice?}`。`voice` 为枚举结果里的 `{renderId,captureId}`；省略表示保留，null 表示移除。接口重新枚举并验证设备，校验版本后原子保存。返回新状态和 `saved:true,restartRequired:true,servicesStarted:false,inputSent:false`。

开启时写入 `enableInput:true,allowSubmit:true`，关闭时两者均为 false。保存过程不生成 Reader token，不改变目标联系人，不启动 DSH 或发送服务。并发配置变更会被拒绝；开启保存期间持有发送服务的启动锁，防止“保存”和“启动”同时发生。未确认结束的旧服务或录音记录不会被此接口清除。

## 未知录音的本机恢复

“检查语音恢复状态”只读检查当前账号、停止状态、原录音记录及本机输入程序。确认微信录音界面已经关闭，并查看对应聊天的消息结果后，分别勾选两项确认，再点“解除这次录音占用”。已明确取消并完成清理的普通键鼠打断不使用这个入口；取消结果不明或原读取组件退出未确认，仍须保留占用，停服核对后通过此入口处理。

- `GET /api/ui-runtime-controls/voice-recovery`：返回匿名 `revision`、`available`、`required`、`canRecover`、`attemptCount` 和是否有中断的恢复事务，不返回账号、聊天、音频端点或进程标识。
- `POST /api/ui-runtime-controls/recover-voice`：只接受 `{expectedRevision,acknowledgeRecordingEnded:true,acknowledgeMessageOutcomeReviewed:true}`。重新确认相同账号和配置、全部相关服务与原生输入程序停止，并核对原记录字节和原执行租约；状态变化即拒绝。

恢复过程持有本机配置与服务停止锁，先保存原记录和恢复事务，再解除本次录音占用。中断的恢复事务继续阻止新录音；重新检查后只能续完相同记录，不能借恢复更换 ID。原发送尝试不改写，旧 ID 不重录，消息仍可保持未知；此操作不确认送达、不补发、不启动服务，也不改变发送许可。硬终止留下的归属锁不会被猜测清理。

2026-10-29 已通过正式接口恢复 v5 测试留下的两项配对录音占用：原发送记录字节未变，无服务启动或输入，恢复后没有剩余占用。此事实不把失败的 v5 Enter 提交改为成功，详见 [显示验收矩阵](DISPLAY_ACCEPTANCE_MATRIX.md)。

最新文件传输助手实测中，最终组合语音 V2（驱动 `69bc6c132e5c`、Voice183）完整联系人切换与开始录音占用 968 毫秒，发送并归还占用 281 毫秒；首段包含实际导航和准备。此前文字 V5（驱动 `3beb6a48b8bd`）包含导航、粘贴、Return 与归还为 813 毫秒，两项均取得唯一数据库回执。最终语音的 5100 毫秒接收音频完整覆盖源样本且无新增静音；没有本轮人工听感确认。这些诊断为中文“文件传输助手”查询使用私有原生例外，当时正式好友路径仍使用完整数据库微信号；单次成绩不保证任意环境都低于一秒。

Voice183 的 V12 在外部操作激活现有微信后自动 Esc 取消成功且未尝试发送，取消占用 63 毫秒，从微信已在前台开始，不含外部激活；之后最终 V2 另用新 ID 正常录制成功。这一历史测试尚未覆盖生产队列自行重录、持续真人操作、长期运行和副机部署；当时自动回复关闭，CABLE 默认录音路由按用户选择保留，六项默认音频角色没有改变。后续正式服务已完成真实好友连续三轮文字回复及群成员真实 @ 的文字回复，均取得数据库回执和用户确认；窗口闪动对应的重复取焦点流程已修复，新生产跟踪样本中每次提交只有一次取焦点和归还；用户尚未反馈新版视觉效果。最新快照确认私聊 5 轮、群聊 7 轮共 12 段群回复均送达，无待处理回复，自动回复已恢复。当前许可和服务状态以控制台为准，不以历史测试的关闭状态判断。

## 迁移

`scripts/export-secondary.ps1` 包含未提交的新源码、控制台模块和本文档；排除 state、当前配置、凭据、聊天、标定、设备 ID、依赖环境和模型。副机安装软件后仍需重新准备本机组件、连接本机账号、标定微信窗口、选择本机音频设备和模型位置。主机上保存的配置不能作为副机已验证的证据。

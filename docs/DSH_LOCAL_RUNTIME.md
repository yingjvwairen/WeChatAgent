# DSH 本地运行与开发入口

## 运行关系与验证范围

项目运行于 **DSH Desktop 加本机 WeChatAgent 配套进程**。DSH 插件管理会话与模型调用；配套进程负责微信读取、持久队列、Windows 截图与键鼠输入、GPT-SoVITS 合成和虚拟音频播放。不调用 Codex 的电脑操作工具，不依赖 Codex 登录态。

此前本机文件传输助手已完成受控逐字输入、人工鼠标打断、文字提交和原生语音发送，并取得数据库回执。旧单次预览路径的一条 5 秒达妮娅短句获手机确认“完整流畅”；这项试听结论不自动延伸到后续版本。

当前代码已接入本地 Reader 初始化、账号激活、Qt 视觉驱动、文字/语音队列、DSH 来源授权、名单切换、启动监督与事件游标。历史 Qt 版本已通过独立截图、空草稿检查、文字输入与读回、剪贴板恢复和文件传输助手自动提交，并取得唯一数据库文字回执。历史特定源码与布局下的完整私聊导航曾通过自身账号、搜索行完整微信号、打开后的资料、空草稿及焦点归还核验，没有向真实好友发送消息。当前共享自适应模式的私聊搜索优先使用公开微信号；没有公开微信号时，只使用当前数据库中唯一映射到该联系人的备注或昵称，然后使用专用 Return。内部稳定 ID 继续用于对象选择、授权和回执，不直接把内部 wxid 当作可搜索微信号。查询和正文都不读回，也不检查空草稿。备注／昵称回退已在一条真实私聊回复中取得唯一数据库回执，含导航连续前台占用为 1,375 毫秒；该单例不保证所有联系人或一秒以内；不增加界面身份核验或查询、正文读回。此前驱动的私有文件传输助手单例已完成导航、正文粘贴、Enter 和焦点归还，连续前台占用 813 毫秒并取得唯一数据库回执；该诊断采用独立的文件传输助手中文查询例外，该单例不能代替其他好友搜索路径或 DSH 自动回复验收。

较早的两阶段监测预热与鼠标归还版本曾向文件传输助手发送一条 5.22 秒原生语音，并取得唯一数据库回执。该次开始、后台录音、提交分别约 657、4782、406 毫秒，两次焦点及鼠标归还均确认，未留下执行屏障；自动转写并非逐字相等。这是当时版本的单次记录。2026-10-28 后续已完成副屏语音单例、系统缩放与分辨率定位，以及当时语音程序在 125% 下的 5.28 秒语音和接收音频校验。该 v4 单例开始录音、结束提交各占用 766、406 毫秒，均不含联系人切换；完整流程、持续自动回复及各显示组合的状态以 [显示验收矩阵](DISPLAY_ACCEPTANCE_MATRIX.md) 为准。共享模式仍为实验功能，不能把这些单例推广为全部场景通过。

接收媒体使用数据库与本地微信缓存。实际图片、视频、引用图片以及合并转发中的图片、视频和引用图片均已通过精确消息绑定与解码。DSH 独立界面会话还实际接收了由这些缓存生成的 3 张视频采样帧、1 张引用图片及自动转写，正确描述蓝色背景、偏左上的红色块、采样时刻的变化范围、讲话大意与历史来源；比例与精确几何不作为通过指标。私有证据为 `state/diagnostics/media-acceptance/reference-forward-live/dsh-ui-packet/semantic-result.json`。这项 UI 语义验收未创建好友入站事件、未调用发送队列；`productionHttpIncomingE2E` 和 `outboxUsed` 均为 `false`，不能据此宣称生产 HTTP 入站至自动回复的真实端到端验收通过。详见 [音视频接收验证记录](AUDIO_VIDEO_INPUT.md#验证记录与限制)。

## 运行时来源

DSH 目录需要包含：

- resources/runtime/primary-runtime/dependencies/node/bin/node.exe，Node >= 22.13。
- resources/runtime/primary-runtime/dependencies/python/python.exe，Python 3.12。

ui-runtime.ps1 和副机入口显式使用该目录。子进程清除 CODEX、NODE_OPTIONS、NODE_PATH、PYTHONPATH、PYTHONHOME 等继承设置；退出后恢复调用进程环境，不改全局 PATH。副机入口保留已安装的 CUDA/FFmpeg 路径，同时过滤开发工具缓存。

截图与输入执行器使用 Windows API 和 .NET Framework；OCR、Reader、GPT-SoVITS 分别使用独立环境。运行时移动、微信程序哈希、版本或布局变化会拒绝继续，不改用未知运行时或旧坐标。

    & .\scripts\ui-runtime.ps1 -Task configure -DshRoot '<DSH安装目录>'
    & .\scripts\ui-runtime.ps1 -Task check
    & .\scripts\ui-runtime.ps1 -Task demo

本机配置保存于 state/ui-runtime.json。check 检查运行时和组件，demo 是离线队列演示；成功不代表真实聊天身份已核验，不启动自动回复。test 在独立环境执行回归测试。InstallOcr 选项安装固定 OCR 依赖，不安装语音模型。

## Reader 准备、连接与账号激活

控制台界面模式的连接入口调用 reader-local-prepare.mjs：按明确选择的数据库目录发现账号、准备 Reader 独立环境，保存与微信程序版本和哈希绑定的请求，再连接并激活同一账号。

已有连接请求时，可使用开发入口：

    & .\scripts\ui-runtime.ps1 -Task reader-setup -TaskArgs @('--check')
    & .\scripts\ui-runtime.ps1 -Task reader-setup -TaskArgs @('--connect-and-activate')

check 只检查本地请求与组件，不证明数据库或桌面状态。无有效缓存时，连接 helper 等待初始化；提示组件就绪后，用户手动退出微信并重新登录同一账号。密钥仅以当前 Windows 用户保护的 DPAPI 格式存于本机，不打印到聊天或日志；有效缓存优先验证，无需重复取钥。

connect 仅连接并保存凭据；activate 激活已有有效配置；connect-and-activate 合并两步。激活统一更新 WeFlow-config.json、active-account.json 和 wechat-ui 正式配置，要求服务已停且账号未变。它不宣称桌面身份已验证，也不自动发送。

连接组件清理或进程退出不确定时保留恢复锁，不能自动重复加载。DPAPI 凭据、读取环境和发现记录不能复制到副机。连接组件固定来源与哈希，但哈希相同不等于完整原生源码审查。

## 本机组件、标定与启动

控制台“设置 → 开发者选项 → 准备本机组件”调用 prepare-ui-components.ps1。构建脚本的 SelfTest 运行合成测试，不访问真实 UI 或播放声音：

    & .\scripts\build-frame-capture.ps1 -SelfTest
    & .\scripts\build-account-probe.ps1 -SelfTest
    & .\scripts\build-draft-probe.ps1 -SelfTest
    & .\scripts\build-qt-actions.ps1 -SelfTest
    & .\scripts\build-audio-probe.ps1 -SelfTest
    & .\scripts\build-voice-probe.ps1 -SelfTest

当前微信 UIA 不提供完整身份与编辑器信息，正式界面模式使用 QtVisualDriver。它结合独立截图、联系人唯一映射、进程账号旁证和受控草稿读取。共享自适应模式的私聊搜索优先使用公开微信号；没有公开微信号时，只使用当前数据库中唯一映射到该联系人的备注或昵称，按专用 Return；内部稳定 ID 继续用于选择和回执，界面标题只用于发现变化。普通模式另核对资料页完整微信号。

`qt-calibrate.mjs --plan <绝对路径> --save` 保留为首次配置或诊断时的手工区域入口，按本机方案只读测量并保存 `state/ui-runtime/qt-visual.json`。正式发送驱动另接入自动布局：在新任务开始时发现客户区尺寸或 DPI 改变，会重新识别当前分隔线、编辑框、搜索/发送控件等锚点并复核完整像素；只改宽、只改高、同时拉伸，以及分辨率或缩放改变后，都不要求简单地按旧坐标缩放或每次手填区域。当前支持的客户端外观和实测范围见 [本地 OCR 与自动定位](LOCAL_OCR_RUNTIME.md#动态布局候选)、[显示验收矩阵](DISPLAY_ACCEPTANCE_MATRIX.md)。识别不明确时会停止，已经有草稿或输入事务时不在中途换布局。布局候选仍不等于空草稿或联系人授权。

语音还要求本机 CABLE 输入输出设备和已核验的录音入口。自适应录音会在录音界面出现后识别取消/提交按钮，并绑定本次实际区域与完整像素；这些识别仍须通过账号、目标、音频会话和活动检查。普通模式核验空草稿；共享模式按用户选择跳过草稿检查，会话明确记录 `draftPolicy:'unchecked'` 和 `emptyDraftConfirmed:false`。窗口变化由自动布局重新核对，未知微信版本或主题会停止；换机时仍需重新建立账号、运行时与音频端点绑定。

正式桥接配置通常为 state/ui-bridge/config.json，引用窗口配置并明确 enableInput、allowSubmit；不保存 Reader 私有令牌。Reader 当前账号、地址与令牌由监督进程在内存中传给桥接。

账号激活、DSH 插件和标定完成后：

    & .\scripts\manage.ps1 start
    & .\scripts\manage.ps1 status
    & .\scripts\manage.ps1 stop

管理器区分 wechat-hook 与 wechat-ui。后者由 ui-service.mjs 管理当前名单 Reader 与 OneBot 桥接；名单版本变化时，先等待旧输入、桥接及 Reader 停止，再启新代次。停止未确认时不继续重启。

## 回复与模型生命周期

“聊天”管理回复对象，“概览”管理电脑使用方式，“能力 → 能力目录 → 语音服务”管理识别和合成方案。每条回复入队时固定输出方式，后续更改不把已经开始或不确定的语音改成文字。

文字回复及多媒体理解使用“设置 → 连接”中的 DSH 模型提供方与模型标识；它们与 GPT-SoVITS 音色方案分别配置。更换 DSH 模型后，保存设置，在诊断页准备配置，从托盘完整退出并重开 DSH，再重启服务；启动检查会拒绝尚未加载当前模型或插件版本的实例。模型标识需要与本机 DSH 配置一致，图片和视频画面理解还要求该模型支持图片输入。这里的模型设置不是无需重启的即时切换。

VoiceProfileStore 在整个合成任务中锁定 GPT、SoVITS 与参考音频；音频保存实际模型标识。NativeVoiceOutbox 将音频保留采样地拆为不超过约 7.5 秒的原生气泡，逐段确认。模型切换不确定时暂停，不把旧参考音频与新权重混用。

模型服务通过 dania-start.mjs 或副机 voice-server 入口启动。只有新启动且仍由启动器持有的实例能清除模型切换不确定状态；历史回执不证明当前服务仍加载该模型。

2026-10-28 使用项目启动器新建的本地服务完成达妮娅方案加载回执，并通过正式预览入口生成 5.04 秒、32 kHz 单声道 WAV；未播放或发送。启动器随后正常清理自己创建的服务，端口释放、自动回复仍关闭、默认配置未变。本地 ASR 已能读出语句，但逐字比对因繁简体和同音字差异未通过，不能据此声称音频内容或音色验收通过，也不能只凭转写差异断言合成发音错误。当前仅有一套完整角色权重，没有进行两种角色之间的真实切换。

关闭服务请求取消并等待原生进程退出。发送超时保留工作锁、输入或录音屏障，不能凭杀进程请求声称已停止。已确认任务归档保留 ID 与回执，未知任务不因归档解锁。

## 游标与读取恢复

事件游标存于 state/ui-reader-cursors。收到事件先持久化，桥接确认接收后推进游标；重连使用同一游标和稳定事件 ID。名单变化建立新基线，不回放历史名单。

Reader 恢复运行后按持久化分页位置自动补读离线消息。诊断页的“读取记录修复”显示扫描时间、待确认事件数和补读进度。群聊和私聊均按当前聊天的原有规则判断是否回复，包括参与方式、唤醒条件和助手权限。

旧版恢复事务中断时，停服后按当前记录版本回滚原日志与游标，再启动服务继续补读。旧页面的普通重建请求会被拒绝，不能清空日志或将读取位置跳到当前时间。读取补读与发送侧的录音、草稿及未知提交恢复分别处理。

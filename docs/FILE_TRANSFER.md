# 微信文件通道

聊天名单中的会话在聊天模式和助手模式下均可收发微信文件。聊天模式使用此聊天独立的文件区，可保存和回传附件。助手模式由指定的管理员发起，可处理和回传当前 DSH 工作区中的文件，读取与处理沿用 DSH 工具权限。详见 [助手模式](ASSISTANT_MODE.md)。

接收链路从 appmsg-6 文件卡片登记引用，按账号、聊天、发送者和原消息定位。模型调用 `wechat_file_receive` 时，读取器复核原消息，并按消息摘要匹配电脑微信已下载的文件。没有摘要时，读取器在当前账号的文件缓存中查找近期写入的同名同大小文件。只有一个候选时，直接复制到当前文件区，并核对本机副本摘要。

如有多份候选，在电脑微信的原消息中打开文件所在文件夹。在控制台打开对应聊天的「任务与文件 → 确认收到的附件」，填写助手提供的附件 ID，再选择刚定位的缓存文件。

确认仅接受当前账号缓存中的普通文件。之后请机器人按原附件 ID 重试，读取器会复核原消息、聊天授权和选定文件的内容摘要。文件被移动或修改后需要重新确认。助手模式下也可直接把原附件另存到这个 DSH 会话的工作区并提供相对路径。

发送链路：`wechat_file_send` 核验当前文件区的相对路径 → 暂存不可变文件副本并登记传输记录 → 独立后台队列调用统一桌面发送器 → 核对新的 appmsg-6 消息及非零服务器回执。排队及原生接口接受请求均不等于送达。不确定的提交不会自动重复发送，等待回执时不占用文字发送锁。

单文件上限为 50 MiB。最多可同时暂存 128 个待发送文件，合计 512 MiB。任务结束后会释放发送副本；仍待核对的回执可在重启后继续查询。控制台显示当前任务和最近 128 条有权查看的历史记录，更早的记录可用原投递编号查询。运行记录与发送副本位于程序数据目录的 `workspace/state/files/`。聊天模式的文件区位于 `workspace/state/files/chats/`，按账号、会话和聊天名单授权隔离。助手模式的接收副本保存在当前工作区的 `.wechatagent-files/incoming/`。接收副本按账号、聊天、发起者和消息编号整理。

用 `wechat_file_send` 发送 PNG、JPEG 或 GIF 时，会沿用文件名和原始文件内容。聊天中的配图和动态表情使用各自的发送入口。

## 桌面发送与回执

文件通过已登录的微信 4.2.0.53 窗口发送。OCR 和 UIA 共用队列，发送时需要短暂借用焦点。输入或提交状态不明时，保留原投递供回执查询和人工恢复。

微信打开文件确认框时，发送器会复核当前弹窗、收件人、文件名和发送按钮。OCR 模式使用弹窗画面核验并点击发送。文件名截断、弹窗遮挡或内容变化会暂停此任务，供操作者在微信核对。

有文件摘要时，回执必须与暂存文件的摘要匹配。消息没有摘要时，提交时间窗内唯一的同名同大小出站文件及其服务器编号即可确认送达，队列同时注明内容摘要未核实。同一服务器消息只确认一次投递。确认文件对话框关闭且焦点归还后，其他聊天可在查询回执期间继续发送。同一聊天的队首文件暂停时，后面的文件继续等待。

桌面队列接受表示请求已登记，只有匹配当前账号、目标聊天、文件元数据及非零服务器 ID 的数据库消息才表示已确认。文件的工作区范围、不可变副本、管理员与聊天授权继续在实际输入前复查；移除后重新添加聊天不会恢复旧授权。

文件进入桌面队列后即释放入队处理名额。后台使用独立名额查询回执，其他聊天仍可提交已登记的文件。

Reader 临时不可用时，文件任务保留原投递编号和截止时间，连接恢复后继续核对。两分钟截止时间限制新的输入：尚未输入的任务到期取消，已有草稿的任务保留人工恢复提示，已经提交的任务继续核对原回执，结果由桌面队列确认。全局暂停期间可以确认已经提交的文件。只有当前账号的活动队列和归档均确认原意图尚未入队且未到期，才会续接入队。撤回授权后停止后续输入。已经交给桌面队列的文件仍可在原账号按投递编号核对结果，结果不明确时保留为“未确认”。

操作被打断或微信里留有文件草稿时，按[桌面发送与恢复](FOREGROUND_INPUT.md#发送与恢复)核对该聊天的消息和输入框。

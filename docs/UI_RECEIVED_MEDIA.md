# 微信界面发送模式的消息接收

`wechat-ui` 的接收来自当前账号的本地微信数据库。截图用于定位发送界面，不用于逐条识别收到的消息。接收覆盖控制台选中的私聊和群聊；取消选择或切换账号会撤销旧的读取服务和附件访问。群消息分别保留群身份与实际发言成员，@ 判断读取同一数据库消息行的 `msgsource/atuserlist`，包括 @所有人，不把正文中的“@昵称”当作真实提醒。

已接入的入站类型：

- 文字保留原文。
- 图片与表情使用消息绑定的本地缓存、现有解码器和图片摘要校验。表情动画提供静态画面或采样画面。
- 引用回复分别保留当前回复与历史引用。引用图片、表情、语音或视频时，只在同一已授权会话按原消息编号、类型和作者查唯一原消息，再注册附件；不把原消息重放成新发言。
- 合并转发保留作者、时间、正文和嵌套层次。卡片里的图片、视频与语音还需绑定完整卡片摘要、条目路径和条目摘要，读取前后重新核对卡片数据库行。转发中的引用回复保留正文，并按同一聊天的唯一原消息绑定引用附件。不能把卡片内的任意路径或链接当附件读取。
- 语音和视频进入本地媒体处理模块。转写与画面解析结果由 DSH 插件按原会话取得；不可读取时提供明确说明。

图片、引用和转发不是普通文字伪装的附件。消息流只携带随机外观的摘要引用；数据库路径、媒体密钥、原始 XML 和读取服务令牌不会进入模型消息。DSH 插件通过当前运行服务的鉴权代理取得媒体，前后核对账号、名单版本与目标授权，不复用旧读取器的令牌。

读取服务将消息日志和附件索引持久化在受限本地目录中。确认接收后才推进流游标；重启保留同一事件身份，防止重复触发。首次启用只建立当前基线，不自动回复历史聊天。

## 范围与无法读取的情况

图片和表情依赖当前账号已有的可验证缓存。普通图片、表情的缓存命中也在返回前后重查原消息的账号、聊天、发送者、类型、编号、时间与元数据摘要；旧版未保存该绑定的缓存需要重建。引用原消息被删除、原消息编号缺失、类型或作者不符、多个数据库分片出现歧义时，不猜测替代附件。合并转发中的音视频已接入卡片与条目绑定、本地完整内容摘要校验和既有处理器；真实转发图片、视频及转发中的引用图片已完成下述缓存验收。文件、位置、其他应用卡片及系统消息不在这次接收扩展的验收范围。

部分 type 47 动画表情使用账号本地密钥加密。读取器按需从当前 Windows 用户固定 `APPDATA/Tencent/xwechat/net/kvcomm` 目录的统计文件名取得有限候选，不读统计文件内容、不扫描进程内存，也不注入微信。只有当前账号派生密钥解出的完整字节 MD5 与已经绑定的消息 XML 一致，才接受缓存。密钥与候选不写入模型消息或日志；目录联接、符号链接、超量目录或文件被拒绝。没有缓存、没有可验证候选或摘要不符时，继续明确返回不可读取，不用原测试文件或其它消息替代。

已选聊天中的本人历史附件可以成为引用或转发的读取来源，仍需完整消息身份绑定。自己的新消息继续被入站事件过滤，不会因附件可读取而触发自动回复。

每张转发卡片最多展开 50 条历史记录、3 层嵌套，最多绑定 4 张图片与 2 个音视频附件；单批模型输入继续遵守现有图片数量和大小预算。图片模型不可用或本地附件缺失时，模型收到不可读取说明，不能据此编造内容。模型实际推理是否在本机取决于 DSH 中选择的模型服务。

## 本地验证

`scripts/test-ui-incoming-content.mjs` 验证当前 `UiOneBotBackend` 到 OneBot 归一化的类型、历史来源、账号与名单授权、重复事件和不可信路径隔离。

`scripts/test-reader-incoming-media.py` 使用真实只读 SQLite、PNG 文件和本机鉴权 HTTP，验证同一消息的附件身份、图片摘要、撤权、错误账号、重启索引、原消息引用和篡改内容。它不操作桌面、不发送微信消息，也不把受控样本当成真实联系人消息。

`scripts/test-wechat-nested-media.mjs` 验证转发附件的卡片、路径和内容摘要绑定，以及真实合成 MP4/WAV 的本地解码。真实微信验收另外使用文件传输助手的受控消息：普通视频 type 43、引用图片 type 49/57、合并转发 type 49/19 中的图片、视频及 `datatype=1/refermsgitem` 引用图片，均从当前账号的实际微信缓存解析成功。引用与两处转发得到同一张 640×360 图片；转发视频解析得到 4.56 秒、3 张采样帧及本地音轨转写。资源记录只作为缓存文件名提示，实际媒体字节仍需匹配消息声明的 MD5。

2026-10-27 又通过微信界面向文件传输助手发送了受控的两帧 GIF。精确时间窗内唯一消息确认为 type 47；正式读取器从当前账号实际的加密 Emoticon 缓存解出 855 字节、128×128、两帧不同画面的 GIF，完整 MD5 匹配原消息，生成 256×128 的动画采样图，并在返回前后通过原消息身份和元数据重验。该验证未访问微信进程内存、未使用 CDN，也未将源 GIF 冒充接收到的缓存。

合并转发中的加密表情及转发里的 type 47 引用也复用上述受限解码：只将当前已验证条目中的内容摘要传给解码器，不传卡片中的路径、链接或密钥。真实微信 4.1.15.56 的转发表情使用 `dataitem datatype="37"`，摘要位于唯一 `emojiitem/md5`，与普通转发图片的字段不同；现已独立解析，并在入站附件保留表情类别和历史来源。

2026-10-27 23:54:49 又通过微信界面将上述动画表情合并转发给文件传输助手。精确时间窗内唯一自身发送的 appmsg/19 卡片包含一个 datatype 37 条目，正式受限读取器完成注册、实际缓存解密与父卡/条目/会话绑定重验，生成 256×128 采样图，其 SHA256 与先前已验证的真实 type 47 缓存预览相同。本次也没有进程内存读取、注入或网络取图。离线测试另外拒绝重复 emojiitem、重复 MD5、嵌套伪摘要和以缩略图摘要代替表情内容；转发里的 type 47 引用仍由独立测试覆盖，不将本次直接转发表情实测外推为所有嵌套形式的实测。

上述实际样本由本人发送，正式入站过滤仍忽略这些自身消息；这项结果验证消息绑定与缓存解析，不声称真实好友入站到自动回复的整条链路已实测。正式事件与插件 HTTP 接线由隔离集成测试验证。`scripts/test-wechat-sticker-local-key.mjs` 另覆盖本地候选、错误账号、错误摘要、链接、大小与数量上限的离线边界。私有记录保存在 `state/diagnostics/media-acceptance`，不进入源码包。

后续补齐了微信适配层对 `record` / `video` 的接收，避免已解析的语音或视频在进入社交引擎前被过滤。只有类型、摘要引用与消息段一致的媒体才能通过，普通外部音视频链接不能冒充已读取附件。`scripts/test-native-session.mjs` 中两条完整隔离测试使用实际名单授权、反向 WebSocket 接收确认、社交引擎、DSH HTTP、当前读取服务的媒体代理和持久发送队列；验证转写与采样帧进入模型输入、回复只排队、重放不重复处理、撤权后只读查询不重发。媒体源和模型输出是明确的测试夹具，发送队列保持暂停，没有桌面输入或真实微信发送。

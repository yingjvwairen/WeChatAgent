# 手动管理表情包

「表情包 → 我的表情」提供两个独立来源。上方的**项目本地图片与 GIF**可在没有微信账号、没有读取服务时从本机文件夹导入，最多保留 1000 项名称、标签和原文件引用；机器人直接在已授权聊天中选用，无需再导入账号池。删除库内条目不会删除源文件，发送时重新核验原文件哈希。下方的**账号共享表情池**保留聊天收集、账号隔离和满池评选。

从已有的版本 1 本地素材库迁入时，在项目目录运行 `node scripts/import-reply-media.mjs --source "D:\Backup\state\reply-media\config.json"`。将示例路径换成备份配置的实际位置。安装版可以在数据目录的 `workspace` 中执行同一命令，使用安装目录 `app/resources/runtime/node.exe` 提供的 Node.js。需要写入其他工作区时，用 `--root` 指定其路径。导入要求目标工作区尚未创建本地素材库，名称、标签和启用状态会随配置保留。素材仍引用原文件，请保留原路径。

在添加窗口勾选“PNG 和 JPEG 保留原图，作为普通图片回复”，即可把静态素材按原始字节导入当前账号的共享池。在微信 4.2.0.53 前台发送模式下，模型可以按描述、标签选择这些普通图片或原有 GIF 表情。每条素材的引用只对本次授权聊天有效，撤销聊天或移除素材后无法继续提交。普通图片确认送达需要当前账号、目标聊天和提交时间窗内唯一一条内容匹配且有服务器 ID 的出站消息。Reader 可以核对源文件摘要，也可以读取绑定到该记录的本地完整图片，比较尺寸比例和图像特征，以识别重新编码后的图片。证据缺失或匹配有歧义时，原投递保留为待核实。发送器确认编辑框已释放后，其他任务可以继续。

当前界面位置见[导航与设置说明](UI_LAYOUT.md)，旧链接仍可跳转到对应页面。

保存微信账号的本机读取配置后，打开左侧「表情包」，切换到“我的表情”。导入、编辑、删除和预览由控制台本地组件完成，读取服务未启动时也可使用；不读取聊天数据库或调用模型。

使用「从文件夹添加」可以一次导入整个文件夹顶层的图片。点击「开始添加」后按文件名逐张处理，跳过子文件夹、其他类型和已经手动入库的表情。重复导入会保留已有的名称、描述和标签。文件夹导入与单张导入使用相同的账号、图片上限和表情池容量。

- **添加**：点击「添加表情包」，一次选择 1–20 张本地 GIF、PNG、JPG 或 WebP。每张最多 20 MiB、边长最多 4096 像素、单帧最多 400 万像素，动图最多 200 帧，所有帧合计最多 8000 万像素。GIF 保留原始动画；PNG/JPEG 可勾选保留原图，其余格式转换为 GIF。
- **编辑**：为表情填写准确的内容描述和最多 6 个标签。机器人根据这些描述与聊天内容选择图片。手动添加和编辑均不会调用模型。
- **删除**：点击卡片「删除」并再次确认。删除只影响当前账号池内副本，保留源文件与微信聊天记录。已开始发送的消息可能继续完成。
- **预览**：点击卡片图片查看完整表情，支持 GIF 动画。

手动添加与聊天收集共用当前账号的 50 张池子。相同图片合并，不重复占位。满池时手动添加会提示先删除，不自动覆盖；之后自动收集触发的 DS 满池评选仍可能替换池内表情。

手动添加的资源可用于当前账号的所有已允许聊天，即使关闭自动收集或「聊天来源共享」。聊天收集的资源仍按原来的来源、共享开关和聊天范围授权。每个聊天的表情发送开关仍生效；不同账号的资源不混用。

导入、编辑和删除立即保存，无需点击全局「保存设置」。账号或池内容在操作期间变化时，操作会中止并提示刷新，避免覆盖新内容。批量添加逐张处理，失败时显示每张的结果，已成功的图片保留；不会把图片导入任务提交到聊天会话或等待模型回复。

数据位于 `state/stickers/collected/<账号目录与账号标识的摘要>/`，索引为 `index.json`。手动删除会清除池内文件和引用，并让旧评选结果失效；短名单记录最近删除的 512 张图片，阻止它们被自动收集立即加回。再次手动导入可以恢复。

控制台和在线读取器共享同一账号素材池及跨进程事务锁，互不覆盖导入或收集结果。切换账号后重新读取对应的素材池，旧页面不能编辑新账号的资源。

本地素材和账号共享表情先按匹配程度排序，等分候选交替取自两个来源，再按唯一 ID 截取前 20 项。停用素材库或编辑单张素材时，控制台只提交变更。素材目录最多 1,000 项，保存前检查清单的 UTF-8 字节大小。

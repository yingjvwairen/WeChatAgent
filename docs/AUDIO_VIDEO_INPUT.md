# 微信语音与视频接收

Reader 从已选择聊天读取语音和视频，在本机解码音轨和提取视频采样帧。语音识别默认使用本地 faster-whisper。选择云端时，Reader 将解码后的音轨提交给配置的识别接口，再把转写和采样帧交给当前 DSH 模型。

## 配置

在控制台的「能力 → 语音服务」分别选择语音识别与合成后端。云端识别填写兼容 OpenAI `audio/transcriptions` 的完整地址、模型和服务需要的密钥。云端合成填写兼容 `audio/speech` 的完整地址、模型和音色。识别接口接收 multipart WAV 并返回 JSON `text`，合成接口接收当前回复正文并返回 PCM WAV。设置全局生效，后续任务读取当前选择。

完成 Reader 配置后，运行媒体准备程序。使用本地识别时还需要先准备达妮娅运行环境。

```powershell
node scripts/prepare-local-media.mjs --download
```

准备程序在 `state/media-processing/venv` 创建独立 Python 3.12 环境。云端识别只需媒体解码依赖 `silk-python`、PyAV 和 FFmpeg。本地识别还会安装 faster-whisper，并复用达妮娅 Python 环境中的通用依赖。首次由云端切换到本地识别时，请运行准备程序安装本地模型。

在「语音服务 → 语音识别」选择本地后，右侧可切换识别方案。默认的 Small 自动检测语言，「Small · 中文」使用同一份权重并按中文转写。展开「编辑识别方案」可新建命名方案，选择模型目录、指定语言，并填写人名或术语作为识别提示。改好方案后，点击底部的「保存语音服务」，再点识别方案旁的「使用此方案」。显示「识别模型已常驻」后，后续语音和视频音轨都会复用该模型。

关闭控制台网页后，识别模型仍会常驻。切换识别方案、调整当前方案的模型目录、语言或提示词，或改用云端识别时，点击「保存语音服务」后程序会自动释放旧模型。从桌面应用的托盘菜单选择「退出应用」也会释放识别模型。下次需要本地转写时，再点击「使用此方案」。

Small 主模型文件约 484 MB。可运行 `npm run media:prepare -- --model tiny` 或 `npm run media:prepare -- --model base` 安装其他多语言模型，权重分别约 76 MB 和 145 MB。已安装的模型会出现在方案列表中。导入已有 Whisper 权重时，选择包含 `model.bin`、`config.json` 和 `tokenizer.json` 的本机 CTranslate2 模型目录。[默认 Small 权重](https://huggingface.co/Systran/faster-whisper-small/tree/536b0662742c02347bc0e980a01041f333bce120)

本地识别以 CPU/int8 离线加载模型。该模式需要达妮娅环境提供 CTranslate2、ONNX Runtime、tokenizers、huggingface-hub 和 imageio-ffmpeg。

## 消息绑定与处理

- Reader 对每条附件保存账号、聊天、发送者、消息本地编号、服务端编号、类型与时间。对外只输出不含路径的附件 ID。
- 读取语音前重新核对原消息，再按相同聊天、服务端编号、时间，从只读 `VoiceInfo` 数据库取得唯一语音数据。SILK、Tencent SILK、WAV、AMR 走本地解码。
- 视频只读取已经下载到当前账号目录的 MP4。缓存名称可来自精确服务端编号、本地编号与时间匹配的 `MessageResourceInfo` 资源记录，消息 XML 中的 MD5 仍必须和本地文件真实字节相符。优先使用已发送版本，只有不可用时才回退到明确声明的原始视频版本；不根据显示名称猜测附件，也不追踪 XML 中的远程链接。
- 媒体解析前重新校验当前账号和聊天选择，解析后再次检查。改选、切换账号或 Reader 停止会使相关访问失效。模型插件经运行中的本机适配服务获取受限媒体，不需要获知 Reader 凭据。
- 引用、转发里的已核实附件携带来源位置；转写与画面不会被描述为当前发送者本人说出、拍摄或创作。

单个源文件最多 64 MiB，语音数据库内容最多 8 MiB，时长最多 5 分钟。视频最多一个视频流和一个音轨、最大 3840×2160。每段视频最多采样 4 帧，每帧缩至最多 640 像素宽且不超过 768 KiB；整轮图片与视频画面共享 4 张额度。单轮最多 4 个音视频引用，媒体准备共用 125 秒预算；单个工作进程最多 120 秒。超时、文件尚未下载、摘要不符或识别失败会生成明确的不可用说明，其他可用消息仍可处理。

转写标记为自动识别，可能出现人名、同音字错误。视频帧带有采样时间，明确只提供间隔画面。当前模型不支持图片时，只提供成功的音轨转写并说明没有画面。提帧成功不等于视觉理解成功；只有模型实际接收图像并返回相关内容才算语义验收。

本机缓存包含转写和采样画面，保存在 Reader 私有媒体目录中，按账号和消息绑定。源录音临时文件在处理结束后删除。不要把 `state` 目录提交到仓库或用于公开分发。

## 验证记录与限制

本机已验证：

1. 已确认音色的达妮娅 WAV、从该 WAV 编码得到的 Tencent SILK、带该音轨的合成 MP4 均由本地模型完成转写；合成视频产生 3 帧，时长 4.56 秒。
2. 已授权私聊中一条实际收到的语音，经过原消息与 `VoiceInfo` 绑定、SILK 解码和本地转写，返回 `ready`。实际时长 2.54 秒，处理约 3.33 秒；验收报告只记录字数与摘要，没有向日志输出聊天内容。
3. 自动测试覆盖跨会话拒绝、消息身份/重复数据拒绝、真实文件摘要、画面哈希、失效选择、整轮超时、取消、来源标签与持久缓冲。中文子进程输出显式使用 UTF-8，避免 Windows 默认编码破坏转写。
4. DSH 当前配置的 `deepseek-account/deepseek-flash` 在独立测试会话中实际接收一张合成视频采样帧，识别出蓝色背景、唯一红色实心矩形及其偏左上位置；没有调用工具。颜色、形状和大致位置通过，比例估计有误，未将其视为精确几何测量。该结果验证单帧视觉理解，不等于完整连续视频验收。
5. 一条已确认发送到文件传输助手的 5.18 秒测试语音，按该回执的账号、分片、消息编号、时间、类型与发送者定位，再用唯一的本地语音键及 XML 声明长度取得实际 SILK。该发送端语音行的服务端编号仍为 0，因此验收报告保留了这一绑定方式，未假称直接按服务端编号命中。4.56 秒源音频全部位于实际录音内；音量包络相关性为 0.9974，30 个有声窗口的对齐时差跨度小于 0.4 毫秒，未检测到明显中间丢段或新增停顿，末尾余量约 226 毫秒。源与实录的自动转写仅在人名音译上不同。这是自动内容与波形验收，不是用户试听或音色确认。
6. 合成图片通过微信界面实际发到文件传输助手后，按窄时间窗内唯一图片消息及发送者定位。正式图片解码器从当前账号微信缓存得到完整 640×360 图像，消息绑定、缓存来源指纹和输出摘要均通过；实际缓存图像仍具有预期的蓝色背景和红色矩形。验收没有把本机发送源 JPG 当作微信接收缓存。
7. 合成视频经微信界面发送为原生视频气泡后，精确绑定实际 type 43 消息及资源映射，从当前账号视频缓存读取 41,389 字节 MP4；真实字节与消息 XML 声明的 MD5 一致。正式解析器取得 4.56 秒视频、3 张采样帧和状态为 `ready` 的本地音轨转写。该测试使用微信实际缓存，未把发送源 MP4 冒充接收文件；视觉语义结论仍以上述独立模型验收为限。
8. 实际发送到文件传输助手的引用图片及合并转发卡片中，图片、视频和转发里的引用图片均已按原消息与条目绑定读取成功。转发视频解出 3 帧、4.56 秒与 `ready` 转写；三条图片引用输出摘要一致。自己的消息仍被入站过滤，未伪装为好友消息触发回复。
9. DSH 的独立界面会话实际接收上述微信缓存生成的 3 张视频采样帧、1 张引用图片及本机自动转写。`DeepSeek-V4.1-Flash` 正确描述蓝色背景、偏左上的红色块，指出 760、2280、3800 毫秒三个采样时刻未见变化，但不推断完整连续视频静止；正确概括问候、自我介绍和微信语音测试，并区分历史转发/引用来源。模型把红色块称为方形，比例与精确几何不作为本次通过指标。该结果证明这批实际媒体的独立 UI 语义验收通过，不等于生产 HTTP 入站或自动回复 outbox 的真实端到端验收。验收报告位于私有 `reference-forward-live/dsh-ui-packet/semantic-result.json`。

尚未下载的视频、没有可核实 MD5 的视频格式及超过上述上限的媒体会明确失败。当前实现不承诺理解所有任意文件格式，不会把不可读附件的占位说明当成附件内容。视觉模型实际验收状态应查看本次部署记录，不能从“提帧完成”推断通过。


## 安装、更新与开关检查

音视频接收跟随控制台当前选择的聊天和 Reader 生命周期，没有独立的“识屏接收”开关。GPT-SoVITS 音色开关控制发出的语音；本机自动转写模型控制收到的语音，两者分别配置。切换到不支持图片的 DSH 模型时，视频仍可提供音轨转写，画面则明确不可用。表情 CDN 获取默认关闭，启用本地语音/视频解析不需要打开它。

`setup.ps1` 和副机 `prepare-components` 准备基础依赖及本机执行器，不会自动下载约 484 MB 的转写模型。首次部署或迁移后仍须执行上面的准备命令，再执行 `node scripts/prepare-local-media.mjs` 核验。该核验会刷新本地配置与依赖清单，不能当作完全不写盘的检查。使用本机 DSH 自带的 Node 或独立 Node；不需要 Codex 环境。

更新源码后，运行 `node scripts/project-config.mjs` 更新 DSH 插件修订。该修订已包含 `reader-media-access.mjs`、`image-input.mjs` 和 `media-input.mjs`。在 DSH 中确认安装路径指向当前项目的桥接插件，并完整退出、重开 DSH，使模块和配置重新载入；仅刷新网页不会替换已载入模块。再重启本项目 Reader 服务，保留原有账号和聊天选择。插件健康状态应含 `imageInput: native-attachment-v1` 与 `mediaInput: local-transcript-sampled-video-v1`；这些只证明接口版本，不能代替真实媒体解码或模型理解验收。令牌仅在本机使用，不粘贴到聊天或诊断日志。

源码迁移包排除 `state`，因此不会携带数据库凭据、原消息、缓存、模型环境或旧电脑的窗口标定。另一台电脑需要重新配置账号、Reader、媒体依赖和窗口标定。当前机器已完成的验收不能冒充副机实测结果。

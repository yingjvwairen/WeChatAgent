# 微信语音 API 转写

在“能力 → 能力目录”打开“语音识别 API”，选择服务、填写地址与凭据，读取或填写模型 ID。使用配置页的内置短句测试成功后，启用插件，并为需要转写的聊天授予语音读取权限。

使用本地 Whisper 时，先在连接设置中准备并启用识别服务，再在插件中选择“本机语音服务”。同一聊天只授权一个处理单条语音的插件。[本地 Whisper 设置](LOCAL_WHISPER.md) · [语音识别插件说明](../optional-extensions/speech-recognition/README.md)

## 配套宿主

- `reader-api.py` 接收类型 34，为已启用并授权的插件和聊天登记引用，并随消息写入持久收件箱。文件路径、数据库凭据和音频字节由读取端保管。
- `wechat_voice_input.py` 将引用绑定当前账号、聊天、服务器消息 ID、本地 ID、时间及原发送者；媒体数据库仅查询对应聊天和本地 ID，遇到不同候选字节拒绝选择。
- 带令牌的读取端点 `GET /api/v1/voices/:id?conversationKey=...&pluginId=...&format=wav|silk` 再检查当前账号、聊天和授权；只供宿主使用。
- 插件 API 的 `ctx.audio.read(id,{format,segment})` 需要 `audio_read`，且 id 必须在当前宿主动作的绑定范围内。不会向插件传递读取器令牌或数据库密钥。普通微信语音仍限制 60 秒；视频音轨可达 300 秒，以同一个消息 ID 分成最多五个不超过 60 秒的音频段。宿主在请求 SILK 时将 WAV 分段编码为 SILK，已有原始 SILK 的微信语音继续使用原始字节。`segment` 从 0 开始，每段读取前后重新检查账号、原消息和插件权限。
- DSH 的认证端点 `POST /voice-input` 核对当前账号、聊天授权和发件人后，调用本聊天唯一一个已获 `audio_read` 授权并注册 `transcribe` 动作的插件。助手群的普通成员可以在无工具聊天中使用同一语音授权。结果带回处理插件的 id，转写过程不会创建 DSH 会话或授予任务权限。[聊天能力路由](PLUGIN_DEVELOPMENT.md#聊天能力路由)
- Bridge 先保存原消息和音频引用，再确认收件。聊天进入回复判断时，最多转写当前消息和相关上下文的四个音频引用。唤醒模式的普通群消息和离线背景保留引用，进入后续合规的回复轮次时才读取音频。转写失败保留故障提示。

权限撤销、账号切换或进程停止后，未完成结果会作废。读取和上传有截止时间，全局最多两条识别请求。Bridge 在调用前保存尝试状态。重启时如果只找到尝试记录，会显示 `VOICE_INPUT_INTERRUPTED`，避免为同一入站消息再次上传音频。

插件使用 `ctx.audio.segments(id, options)` 按顺序读取视频的各段音轨，将完整转写合并到原消息。中途失败时会标明识别失败。Reader 补读时，当前聊天获准回复的最后一条语音也使用该聊天授权的识别插件。

## 连接检查与诊断

设置页里的“读取模型”和“测试识别”需要先勾选“允许此插件运行”。内置短句可用来核对地址、鉴权、协议和模型。想检查本机音频解码时，在配置页核对 WAV 转换组件状态。安装包自带 `silk-wasm` 解码组件。

最近一次聊天语音的处理状态按插件保存在 `state/plugin-service-checks/voice-input/`，记录时间、阶段和错误码。遇到转写失败时，先查看此处是读取、转换还是服务调用出错。修改服务设置后重新运行短句测试，再检查该聊天的插件授权。

视频音轨最长五分钟，每段最多一分钟。识别插件默认接受合计 12,000 字符的转写，可在插件设置中调低上限。

遇到成功返回空文本的分段，转写会继续处理后续音轨。所有分段都没有文字时提示未取得转写。权限撤销、音轨读取或服务请求出错时，整条转写失败。

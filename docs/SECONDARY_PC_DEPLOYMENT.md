# 副机运行与推流音频隔离

按副机已经安装微信、DSH、达妮娅所需环境、VB-CABLE 和 OBS 处理。本说明不安装软件，不修改推流配置，也不执行录音或发送测试。

副机是部署位置，不是独立发送模式。微信、DSH、WeChatAgent、语音服务和读取组件全部在目标电脑本地运行；项目没有主副机通信、远程输入或跨机任务分发。源码迁移、路径配置和音频检查工具继续保留，也可用于其他新电脑部署。本地语音方案在点击“使用此方案”后加载。

主电脑或副电脑都使用相同的“UIA 快速模式”开关：开启走 [UIA 控件链路](BACKGROUND_CONTROLS.md)，关闭走 OCR 快速定位与焦点交接。文字正文默认快速粘贴；另有“文字逐字输入”开关，默认关闭，仅改变 OCR 正文，联系人搜索词仍快速粘贴，图片、GIF 和语音不受影响。UIA 始终粘贴，逐字开关在 UIA 下不可操作但保留选择。“微信离屏”仍为 UIA 下独立的窗口摆放设置。旧共享电脑开关及关闭后的长期前台分支不再作为运行选项。两种部署位置都保留操作保护和回执确认；缺少必要控件或窗口绑定变化时暂停，不能把本机控件读取或单例发送成功当作副机已经验收。

部署到副机后，微信模拟输入发生在副机，主机键鼠不被占用；副机有人操作时，本地输入守卫仍暂停相应阶段的前台输入。若两机使用共享键鼠软件或 KVM，将输入切到副机同样受操作保护约束。Windows 虚拟桌面或隐藏窗口不构成独立输入环境。

OBS 的视频源应固定为主机采集卡、已有主机画面来源或指定窗口。若推流捕获的是副机整个桌面，微信窗口切换也可能进入推流画面；双机本身不会自动隔离这条视频线路。

## 音频线路

```text
达妮娅 WAV → 指定的 CABLE Input 播放端
                      ↓
              CABLE Output 录音端 → 副机微信语音

主机/采集卡音频 ────────────────→ OBS 推流混音
真实麦克风/声卡的明确设备 ─────────→ OBS 人声
```

当前原生语音执行器只播放到指定 CABLE 端点，不播放到系统默认扬声器，也不修改默认设备。它要求 Windows 普通、多媒体、通信三个默认录音角色都指向同一个 CABLE Output，然后核对微信实际活跃的录音会话；配置不符会拒绝起录。

UIA 和 OCR 链路使用同一条线路，也不会在回复前后自动切换默认麦克风。日常会议、游戏语音或录音软件如果需要真实麦克风，应在该软件中明确选择它，不能继续依赖已经指向 CABLE 的“默认”输入。控制台枚举并保存 CABLE 设备只绑定端点，不替用户修改这三个 Windows 默认角色；测试脚本恢复音频设置的记录也不代表正式服务具备自动切换功能。

这会影响选择了“默认”输入的其它软件。OBS 的 Windows 输入采集在使用 Default 时跟随通信默认录音设备，不能保留这个选择后再将通信默认录音改为 CABLE。[OBS 官方实现](https://github.com/obsproject/obs-studio/blob/master/plugins/win-wasapi/win-wasapi.cpp)

副机静态配置应满足：

1. OBS 的 Mic/Aux 及场景中的 Audio Input Capture 明确选中真实麦克风、声卡或采集卡设备，不使用 Default。若同一设备已作为场景音源添加，避免又在全局音频里重复采集。[OBS 音频源说明](https://obsproject.com/kb/audio-sources)
2. OBS 的 Desktop Audio、Audio Output Capture 不选择 CABLE Input。需要采集主机声音时，使用明确的采集卡、音频接口或已经配置的主机音频来源。不得因为机器人使用 CABLE，就把推流桌面音频也切到 CABLE。
3. 不把 CABLE Output 加入推流音轨；不为它开启 OBS 音频监听。Windows 的 CABLE Output“侦听此设备”也应关闭，避免机器人声音经扬声器再次进入推流混音。
4. 若使用 NDI、Voicemeeter、硬件混音或其它音频转发，应单独检查其输入和监听线路；仅看 OBS 的一个场景文件不能证明这些线路已经隔离。
5. 音频端点 ID 必须在副机重新绑定。主机的设备名称相同不代表 ID 相同。生产路线仍需明确管理开始前与结束后的设备状态；本说明不会自动切换系统默认录音设备。

## 可迁移和需要在副机重建的内容

| 内容 | 处理方式 |
| --- | --- |
| 项目源码、固定版本依赖清单、达妮娅模型与参考音频 | 可迁移；仍按副机实际路径配置 |
| DSH 可执行程序路径、Python 虚拟环境与模型路径 | 绑定副机安装位置；不复制指向主机绝对路径的运行配置 |
| Reader 的 DPAPI 加密凭据 | 绑定原 Windows 环境，不能作为可直接跨机使用的凭据；副机需本地首次配置 |
| 微信数据根、账号与联系人允许范围 | 在副机按真实登录与数据库重新绑定；不以显示名称代替唯一身份 |
| 微信窗口、PID、进程创建时间、焦点、短期会话 | 必须重新取得；不能复制旧的窗口或会话 JSON |
| 编辑区、起录/取消/发送区、鼠标停放区与像素模板 | 在副机从当前窗口重新取得；支持的版本、主题和 DPI 可自动定位，不能复制旧机器的短期模板。不支持的布局仍需本机适配 |
| CABLE 端点、三个默认录音角色、OBS 音源 | 在副机分别配置，不能沿用主机端点 ID |
| 已发送 ID、回执和未知尝试 | 保留审计意义；未知尝试不得因迁移而自动重发，旧进程锁与临时会话不能直接复用 |

微信 4.1.15.56 的本机受控文字、原生语音已经验证，队列、启动监督和当前截图自动布局也已接入。换机仍需重建账号、运行时和音频端点绑定；本机单例不代表副机硬件、OBS 音频隔离或完整自动回复链路已经验收。当前显示适配的真实证据见 [显示验收矩阵](DISPLAY_ACCEPTANCE_MATRIX.md)。

OCR 链路需要当前微信空白标题栏的**非前台**像素模板，供 Windows 拒绝直接取焦点时执行一次普通点击。支持的自适应布局会从本机当前窗口取得；手动布局入口为 [Qt 标定工具的 `--focus-plan`](QT_VISUAL_DRIVER.md#本机标定)。不能使用活动标题栏模板代替，也不能复制另一台机器或另一个 DPI 的旧模板。UIA 使用实时控件，不依赖 OCR 模板，独立离屏设置不等于完全无焦点操作。微信需保持登录，Windows 会话未锁定，窗口未最小化；OCR 录音起止所用区域必须能验证可见。副屏可以提供更多可见空间，但仍共享鼠标、键盘和前台焦点。移动、拉伸或切换显示设置后，按实际位置、尺寸与 DPI 重新定位，无须每次手动校准；识别失败或版本、主题不受支持时暂停。OCR 历史通过的显示组合见 [显示验收矩阵](DISPLAY_ACCEPTANCE_MATRIX.md)，UIA 当前范围见 [控件模式说明](BACKGROUND_CONTROLS.md)。首次联系人导航与需要键盘的步骤仍占用前台。

## 提供的只读审计脚本

`scripts/secondary-pc-audio-preflight.mjs` 只调用项目自带 `AudioRouteProbe.exe --list` 获取端点元数据，可选择读取明确提供的 OBS 场景集合 JSON。它不打开录音或播放流，不访问微信界面，不更改设备，不读取 OBS 的 service.json，不输出设备 ID、场景源名、窗口标题或推流密钥。

实现接口：

```js
secondaryPcAudioPreflight({ root, obsSceneFile })
analyzeSecondaryPcAudio({ audioSnapshot, obsSceneCollection })
```

也可用 `--audio-report <本地绝对路径.json>` 分析已有元数据文件，或用 `--obs-scenes <本地场景集合绝对路径.json>` 指定场景配置。仅支持本地文件，不接受 UNC 路径；不要把映射的网络盘作为输入。脚本没有网络客户端。

原生 `--list` 源码已补全三个录音角色和三个播放角色的默认设备信息；旧构建缺少字段时，审计报告会注明元数据不完整，不会猜测。当前没有副机，本轮按后续要求完成了本机组件构建、离线测试及受控文字发送验证；没有执行副机设备、OBS 隔离或双机现场验收。

输出中的 `streamIsolationVerified`、`windowsListenRoutingVerified` 和 `readyForUnattendedSending` 保持 false。磁盘配置无法证明 OBS 正在使用的场景、监听、外部混音、最终推流或微信实际录音线路；“没有发现配置风险”不等于这些路径已经验证。
